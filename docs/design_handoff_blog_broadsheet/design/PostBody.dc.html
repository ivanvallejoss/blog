The problem

Notion’s API is slow and paginated. The bottleneck was never CPU — it was waiting. That is exactly what asyncio is good at: waiting on many things at once.

 
async def fetch_all(urls):
    async with asyncio.TaskGroup() as tg:
        tasks = [tg.create_task(get(u)) for u in urls]
    return [t.result() for t in tasks]

Con TaskGroup, si una tarea falla, las demás se cancelan. Ese detalle cambió por completo cómo pensaba los errores.

La concurrencia no hace el código más rápido; hace que la espera deje de ser tu problema.

Event loop en cinco minutos

Un solo hilo, una cola de tareas y una regla: nadie bloquea. Cada await es una promesa de devolver el control. Romper esa promesa con una llamada síncrona congela todo lo demás.

Cuándo no usar async

Si el trabajo es de CPU, async no ayuda. Ahí entran los procesos, o ahora, el free-threading de 3.14.

With TaskGroup, if one task fails the rest are cancelled. That detail completely changed how I thought about errors.

Concurrency doesn’t make code faster; it makes waiting stop being your problem.

The event loop in five minutes

One thread, one task queue and one rule: nobody blocks. Every await is a promise to hand control back. Break it with a synchronous call and everything else freezes.

When not to use async

If the work is CPU-bound, async won’t help. That’s where processes come in — or now, 3.14’s free-threading.
